# Ավարտական աշխատանքի կառուցվածք

**Թեմա.** API մոնիթորինգի վահանակ (probeboard)

> Այս ուրվագիծը նախնական է։ Եթե ամբիոնը տրամադրում է պարտադիր ձևաչափ,
> այն պետք է փոխարինի ստորև բերվածը։

## Բովանդակություն

**Ներածություն**
- Թեմայի արդիականությունը
- Աշխատանքի նպատակը և խնդիրները
- Աշխատանքի գիտական և գործնական նշանակությունը

**Գլուխ 1. Առարկայական բնագավառի վերլուծություն**
- 1.1 API-ների հասանելիության մոնիթորինգի խնդիրը
- 1.2 Առկա լուծումների վերլուծություն (UptimeRobot, Pingdom, Uptime Kuma)
- 1.3 Առկա լուծումների թերությունները
- 1.4 Պահանջների ձևակերպում

**Գլուխ 2. Համակարգի նախագծում**
- 2.1 Համակարգի ընդհանուր ճարտարապետություն
- 2.2 Ծառայությունների բաժանումը և դրանց փոխազդեցությունը
- 2.3 Տվյալների մոդելը
- 2.4 Ստուգումների պլանավորման ալգորիթմը
- 2.5 Ժամանակային շարքերի պահպանման և ագրեգացման ռազմավարությունը
- 2.6 Անվտանգության նախագծում (SSRF-ից պաշտպանություն)

**Գլուխ 3. Իրականացում**
- 3.1 Տեխնոլոգիաների ընտրության հիմնավորումը
- 3.2 Հետնամասի (backend) իրականացումը
- 3.3 Ստուգիչ ծառայության (scheduler/worker) իրականացումը
- 3.4 Օգտատիրոջ միջերեսի իրականացումը
- 3.5 Վիճակագրության հաշվարկը և գրաֆիկների կառուցումը

**Գլուխ 4. Փորձարկում և արդյունքների գնահատում**
- 4.1 Ֆունկցիոնալ փորձարկում
- 4.2 Բեռնվածության փորձարկում (500 մոնիտոր)
- 4.3 Հորիզոնական մասշտաբավորման ստուգում
- 4.4 Խափանումների նկատմամբ կայունության ստուգում
- 4.5 Անվտանգության ստուգում
- 4.6 Արդյունքների վերլուծություն

**Եզրակացություն**
- Ստացված արդյունքները
- Հետագա զարգացման ուղղությունները

**Օգտագործված գրականության ցանկ**

**Հավելվածներ**
- Ա. Տվյալների բազայի սխեման
- Բ. API-ի փաստաթղթավորում
- Գ. Ծրագրային կոդի հատվածներ
